# Matrix Cubed to Genesis Compatibility

Generated by comparing a 98.4%-complete disassembly of DOS Matrix Cubed
(`ECL1.DAX`, 25,063 instructions) against the Genesis engine's 94-opcode
table extracted from the ROM.

- **25,063 instructions**, 71 distinct opcodes used
- **58 of 71** have a directly named Genesis counterpart
- **90.64%** of all instructions are directly covered

## Opcodes without a named Genesis counterpart

numeric position. Where the engines diverge they diverge by renaming as
well as renumbering, so a shared slot is a lead worth checking, not proof
of equivalence -- `0x1D` is `SETTIMER` on the Genesis and `PARTY_STRENGTH`
on DOS, which are plainly different.

## What this means

If `INPUT_RETURN` maps to `CONTINUE` -- which the shared slot and identical
role strongly suggest -- the genuinely unresolved surface drops to about
**2.25% of instructions**, concentrated in four opcodes: `CALL`,
`PICTURE2`, `COPY_MEM` and `SELECT_ACTION`.

`CALL` is the one to worry about. It invokes a native routine, so each call
site needs individual attention rather than a table substitution.

The remaining `UNKNOWN_*` opcodes are unidentified in the DOS engine as
well and together account for under 0.25% of instructions.
